# Interfaz de configuracion de viaje

| ID | Categoría | COMO (Rol) | QUIERO (Acción) | PARA (Objetivo) | Criterios de Aceptación |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **HU01** | Flujo Principal | Pasajero | Establecer un marcador en el mapa como mi destino. | Que la aplicación dispare una alarma cuando ingrese al radio geográfico definido. | **Dado** que el usuario visualiza el mapa, **cuando** mantiene presionada una ubicación, **entonces** la app debe soltar un pin y traducir ese punto a coordenadas geográficas reales. |
| **HU02** | Flujo Principal | Pasajero | Cancelar un viaje en progreso mediante un botón. | Detener el consumo de batería del GPS y anular las alarmas programadas. | **Dado** un viaje activo en segundo plano, **cuando** el usuario presiona el botón de cancelar, **entonces** el sistema debe detener inmediatamente las actualizaciones de ubicación y purgar las notificaciones encoladas. |
| **HU03** | Flujo Principal | Pasajero | Configurar una alerta basada en el Tiempo Estimado de Llegada (ETA). | Despertar con los minutos de anticipación exactos antes de mi parada. | **Dado** que el destino está fijado, **cuando** se calcule la ruta, **entonces** el algoritmo debe usar el tiempo restante de viaje para calcular el momento de activación de la alarma. |
| **HU04** | Flujo Principal | Pasajero | Actualizar las coordenadas de mi destino durante un viaje activo. | Recalcular dinámicamente el geofence y el ETA sin tener que reiniciar la app. | **Dado** un viaje en progreso, **cuando** el usuario mueve el pin de destino a un nuevo punto, **entonces** el sistema debe purgar la geocerca anterior y registrar la nueva ubicación sin interrumpir el proceso en segundo plano. |
| **HU05** | UX y Errores | Pasajero | Seleccionar mi tiempo de anticipación deseado (ej. 10, 15 o 20 minutos) desde un menú de opciones. | Personalizar qué tan pronto quiero que la aplicación me despierte antes de llegar a la parada. | **1.** **Dado** que el usuario coloca un pin en el mapa, **cuando** la interfaz registre la coordenada, **entonces** se debe desplegar un menú con las opciones predefinidas.<br>**2.** **Dado** que el usuario selecciona un tiempo, **cuando** presiona "Activar Alarma", **entonces** el sistema debe registrar el parámetro y comenzar el monitoreo. |
| **HU06** | UX y Errores | Usuario frecuente | Que la aplicación recuerde automáticamente mi último tiempo de anticipación seleccionado. | Activar mi alarma recurrente de forma más rápida sin configurarla desde cero. | **1.** **Dado** que un usuario configura una alarma, **entonces** la app debe guardar este valor localmente usando `UserDefaults`.<br>**2.** **Dado** un nuevo viaje, **cuando** el menú se despliegue, **entonces** la opción guardada previamente debe aparecer preseleccionada por defecto. |
| **HU07** | UX y Errores | Pasajero | Visualizar una alerta o mensaje explicativo si mis permisos de GPS no están configurados en "Siempre". | Estar consciente de que la app podría fallar en despertarme si bloqueo la pantalla. | **1.** **Dado** que el usuario interactúa con la app, **cuando** el sistema verifique los permisos, **entonces** debe validar que el acceso esté en "Siempre".<br>**2.** **Dado** que los permisos son inferiores a "Siempre", **cuando** intente iniciar el viaje, **entonces** se debe mostrar una alerta en pantalla detallando la limitación. |
| **HU08** | UX y Errores | Pasajero | Tener un indicador visual sutil si la aplicación detecta que me he quedado sin internet. | Tener la tranquilidad de que el algoritmo matemático de respaldo está activo y no perderé mi parada. | **1.** **Dado** un viaje en progreso, **cuando** el monitor de red detecte pérdida de conexión, **entonces** la interfaz debe mostrar un indicador visual de estado *Offline*.<br>**2.** **Dado** el estado *Offline*, **entonces** el algoritmo debe registrar automáticamente la geocerca exacta y activar el temporizador de respaldo. |
